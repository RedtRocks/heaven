# Task: photoreal face replies (branch feat/musetalk), Phase 4

Goal: given the Clone's reply audio (WAV), produce an MP4 of the Owner's face saying it, using **MuseTalk** (https://github.com/TMElyralab/MuseTalk, MIT) on a **free Kaggle GPU** (T4/P100). The laptop has no CUDA.

1. **Research first.** Read MuseTalk's README for its current version (1.5 or later), install steps, inference command, required inputs (a reference video of the face), and weights download. Check the Kaggle API docs (https://github.com/Kaggle/kaggle-api) to see how to push a notebook/kernel with GPU enabled, pass inputs (datasets), and pull outputs. Write the findings, with links, in `docs/notes/face-musetalk.md`. Mark anything unverified.
2. **Kaggle notebook.** Create `notebooks/musetalk_kaggle/` with a notebook (or script kernel) plus `kernel-metadata.json` that: installs MuseTalk and weights (cached if possible), reads the Owner's reference face video and a `jobs/` folder of WAVs from an attached private Kaggle dataset, renders one MP4 per WAV, and writes them to `/kaggle/working/out/`.
3. **Provider.** `backend/app/providers/face_musetalk_kaggle.py` implements `FaceRenderer` as a batch job via the Kaggle CLI/API. It uploads the WAV as a new dataset version, pushes and runs the kernel, polls status, then downloads the MP4. It's slow (minutes), so also expose an async job API: `POST /face/jobs` `{text or audio}` → `{job_id}`, and `GET /face/jobs/{id}` → status + mp4 URL when ready. Put it in `backend/app/face/`. Store job files under `data/face_jobs/` (gitignored). Kaggle credentials come from settings (`KAGGLE_USERNAME`, `KAGGLE_KEY`); add them to `.env.example`.
4. **Fallback.** Also implement a cheap `FaceRenderer` that returns a still photo of the Owner (`likeness/face/photo.jpg`) muxed with the audio into an MP4 via ffmpeg (check if `ffmpeg` is installed; if not, document it). The registry picks via `FACE_PROVIDER=musetalk_kaggle|still`.

You can't run the real Kaggle job (no credentials). Unit-test the job flow with a fake Kaggle client, and dry-run anything you can. Report as described in common-rules, including exactly what the Owner must do (record face video, create Kaggle token, create dataset).
